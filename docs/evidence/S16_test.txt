S16 ROM-set loader evidence, 2026-10-08
Code: src/board/romset.{h,cpp} (reads the zip into memory with vendored miniz 11.3.2, src/third_party/miniz, MIT). Table identical to tools/check_rom.py. The loader opens the file with fopen "rb" only (grep for write modes: none) and the shipping build is compiled with -DMINIZ_NO_ARCHIVE_WRITING_APIS (no zip-writing symbols in the binary: nm count 0).

Build commands (native): for f in miniz miniz_tdef miniz_tinfl miniz_zip: gcc -O2 -Wall -DMINIZ_NO_STDIO -DMINIZ_NO_TIME -c src/third_party/miniz/$f.c ; then g++ -O2 -std=c++17 -Wall -Wextra -DMINIZ_NO_STDIO -DMINIZ_NO_TIME tests/test_romset.cpp src/board/romset.cpp miniz*.o -o test_romset
(mingw: same with x86_64-w64-mingw32-gcc/g++ and -static; test links the zip-writing part of miniz to build damaged archives in memory, the shipping flags drop it.)
