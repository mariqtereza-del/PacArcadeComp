T02c evidence: the readable dots, energizers, ghost house counters, power pill start and fruit IN the game (src/rules/rules.h: dots::eat_19CD, dots::power_pill_1A70, dots::fruit_0EAD; src/logic/dots_and_fruit.h) versus the ROM (2026-10-16)

== What was done ==
Three hooks cover the four ROM routines of the step:
  19CD  Pac-Man's tile: eat a dot or an energizer. It contains 1B08 (which ghost counts the dot) and, for an energizer, the power pill start 1A70 as parts of the same run, so one hook does all three. It returns to the caller of the movement routine.
  1A70  the power pill start on its own (the ROM also calls it from 2153).
  0EAD  the fruit, called once every frame (70 and 170 dots).
src/logic/dots_and_fruit.h now reports what happened (which ghost house counter took the dot, whether the task queue wrapped, which way the fruit routine went, which timed-event slot was used); the T01c rules are otherwise unchanged. Pac-Man EATING the fruit (ROM 19A1-19C4) stays original ROM code, as planned.
Each hook adds up the exact Z80 time of the ROM instructions it replaces and leaves the registers, flags and the stack leftovers (return addresses and pushed registers written below the stack pointer) exactly as the ROM does (new helper src/rules/z80ops.h). The "fits in the rest of the frame" rule of T02b applies to all of them.

== How it was proved (tests/test_rules_dots.sh 3000000 1000000) ==
Part 1: 1,000,000 whole calls of EACH routine from random situations (random work RAM and video RAM with many dots, energizers and blanks; Pac-Man on any maze tile; every ghost house flag; the task queue pointer near the end of its page; any dot count; any level 0-255; 0 to 16 timed-event slots in use; garbage in A, F, BC, DE, HL, IX and IY at entry). ROM alone versus hook; compared all memory (work RAM with the stack, video RAM, colour RAM), the cycle count, ALL CPU registers including R, the I/O writes. This is also the garbage-register test: the hook must leave every register exactly as the ROM does.
Part 2: original machine versus the machine with all readable rules so far (random numbers, scoring, dots, power pill, fruit) in Machine::run_frame for 3,000,000 frames; a scripted player plays one- and two-player games; the level number is written into both machines so that every fruit appears and the dot count is moved near 70 and 170. After EVERY frame: all memory, I/O writes, the cycle count of the frame and the CPU registers.
Part 3: four deliberately wrong versions.
Also: the replay (7,273 frames) with all readable rules on = original run = Python prototype; the window program with --rules readable: same hashes (tests/test_rules_dots.sh and run_all).

== Honest limits ==
1. The standalone hook for 1A70 never ran in the 3,000,000 live frames (the ROM calls it from 2153 only in situations the scripted player does not reach); it is proved by the 1,000,000 isolated calls. Its use inside 19CD (2,114 times live) is covered by the 19CD hook.
2. The fallback (the ROM runs its own instruction when the routine would not fit into the rest of the frame) was never needed in the live frames (0 times); isolated calls started near the frame end prove it (about 1 in 5 starts is near the end).
3. A full timed-event table (16 slots taken) and Pac-Man tile positions outside the maze's video RAM are not handled by the hook: the ROM runs instead (never happens in the game).
4. The fruit table is the T01c rule (8 fruits and a level rule), the cherry only appears live in the first level; all level numbers 0-255 are in part 1.
