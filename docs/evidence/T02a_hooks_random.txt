T02a evidence: hook mechanism and random numbers in use (2026-10-15)

What was built
  src/board/machine.h/.cpp: Machine::rules, a pointer to a table of 65,536 entries (nullptr = the standard = the original ROM routines, exactly as before).
    Machine::run_frame: before each instruction, if the table is set and has an entry for the instruction's address, that entry runs INSTEAD of the ROM
    routine starting there. One extra test per instruction when the table is set; none of the machine's behaviour changes when it is not.
  src/rules/rules.h (new): the adapters that put the readable rules (src/logic) into the game.
    return_like_ret(): leaves like the routine's final RET (return address from the stack, WZ, the refresh register R by the routine's instruction count,
      the EI delay cleared, and the same number of cycles as the ROM routine charged, so the frame timing is unchanged).
    random_byte_2A23(): seed from RAM 4DC9/4DCA, logic::get_random_byte (src/logic/random_number.h), new seed written back, answer in A; 111 cycles, 13 instructions.
    Scratch registers (F, DE, HL): left alone in the game; the tests fill them with garbage (rules::poison) to prove no caller reads them.
    rules::table(): the table (this step: one entry, 2A23).
  src/app/main.cpp: --rules readable switches the readable rules on (at start and at every machine restart); Purist mode switches them off; the log says
    "Game rules: READABLE (...)" or "Game rules: original ROM routines". src/app/replay.cpp: the replay tool takes --rules readable too.
  tests/test_rules_random.cpp/.sh (new); tests/run_all.sh runs it with 100,000 frames (PLAN CHANGE: run_all.sh was not in the MAY TOUCH list; the
    checkpoint rule needs the new test in it, as for the T01 tests).

Why charging the ROM's cycles: measured before planning (T02 feasibility): the readable routine run instead of 2A23 gave identical replay hashes both
  with 111 cycles charged and with none, because the routine runs inside the interrupt handler early in the frame. Charging the same cycles keeps even the
  cycle count of every frame identical (checked below), which matters for the larger pieces later.

Honest limits
1. Only the random numbers are in use; the game you play is unchanged (the rules are switched on only with --rules readable; the menu setting comes in T02i).
2. src/logic/README.md and MODDING.md still say the readable code is not used by the game; they are rewritten in T02j (not in this step's MAY TOUCH list).
3. The hook replaces a whole routine at once. For 2A23 this cannot be seen because it runs inside the interrupt handler (no interrupt can arrive in the
   middle). Routines run by the main loop (later pieces, for example the level start 070E) could be interrupted half-way in the original; that case is
   checked by the same frame-by-frame comparison in their steps.
