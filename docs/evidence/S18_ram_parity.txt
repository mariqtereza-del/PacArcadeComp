FINDINGS (details in PROJECT_STATUS.md):
1. Cycle rule of the prototype (read from the z80 package source _z80module.cpp): a frame ends when the instruction that reaches 50,688 ticks completes, the excess is not carried over. The C++ loop does the same (frame cycles = whole instructions, so a frame is 50,688 cycles plus the few cycles by which the last instruction overshoots). The interrupt acknowledge costs no cycles in both.
2. The unmodified harness.Board has no address mirrors; the ROM draws the 'HIGH SCORE' text through C3xx (frame 297, pc 2C8C), which the flat prototype memory loses; the real board and the C++ bus store it at 43xx. First RAM difference between the plain harness and the mirror-correct board: frame 297 (exact frames). oracle_dump.py therefore uses MirrorBoard (harness.Board + mirrors, nothing else). harness.py itself was not touched.
3. The z80 Python wrapper ends a frame early every time its own tick counter crosses a multiple of 100,000 (about every second frame, harness.py does not guard against it), so the prototype's frames are irregular: cut to about 49,300 cycles roughly every other frame. The exact section removes this; the prototype_frames section reproduces it.
4. Frames 1-296 (the whole power-on self-test) were identical in all comparisons from the first run on.
