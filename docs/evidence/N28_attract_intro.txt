N28 evidence: native attract-mode introduction (the character and nickname list and the dot / power-dot explanation of the attract mode): src/game/attract.h (the runner), src/game/attract_prog.h (the instruction list, generated by tools/gen_attract.py from the private traced listing), adapter rules::attract in src/rules/rules.h; 62 hooks in rules::table() (readable rules only), all served by one hook function that reads the address it was entered at.
What is replaced (ROM addresses, no ROM bytes): 03DC-0416 (the start sequence of the attract mode with its eight RST 28h task requests and the state steps 03F4, 03FE, 0401, 0413), 045F-0470 and the introduction steps 0471-04D7 (each draws a character, its nickname or a blank with the helper calls below), 04D8-04F4 and 04F5-051B (the end of the introduction, ending in the loop that writes the sprite colour bytes at 0506), the text helpers 0580-058D and 0593-05A4, and the picture block writer 05BF-05E4 (a 2x3 tile picture with its colours). The helper 058E (+1 on 4E02) was already native in N26 and is used as it is. The calls to routines that are not native yet (0042 text, 0879, 2BA1) and the RST 20h / 28h / 30h queue and dispatch hooks of N12-N16 are reached exactly as the ROM reaches them.
How it works: a run starts at one of the 62 addresses where the ROM can enter this code and ends at the first instruction that leaves the straight-line code: CALL (return address pushed, continues at the called address), RST (same), RET, JP, or running straight on into another entry address (the hook there takes over, so that every entry is counted as the ROM enters it). Conditional jumps inside the code are followed. Every instruction is accounted for: T-states, opcode fetches (prefixed instructions count 2), flags incl. the undocumented ones, WZ, the stack bytes.
