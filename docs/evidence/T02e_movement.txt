T02e evidence: movement of Pac-Man and the four ghosts in use (2026-10-16)
Readable code: src/logic/movement.h (pacman_move got one extra option, "eat", so the game can leave the dot part to the already switched-on 19CD rule); adapters in src/rules/rules.h (namespace movement); the model of the ROM's leftovers is src/rules/z80sim.h.
ROM routines replaced when "--rules readable" is on: 1806 (Pac-Man's movement; it hands over to the 19CD rule for dots and energizers), 1B36 (Blinky), 1C4B (Pinky), 1D22 (Inky), 1DF9 (Clyde), with all their helpers (2000, 2018, 2052, 205A, 0065/202D, 1ED0, 1EFE-1F73, 20D7, the task queue pushes).
Purist and the normal game are unchanged: they always use the original ROM routines.
How it works: the readable rules change the game state. The model in z80sim.h walks through the same instructions as the ROM routine (same branches) to get the exact time, the registers and flags the routine leaves, and the stale values it leaves on the stack (the frame hashes include them). It never decides what happens in the game. When the model meets something it does not cover (a tile address outside the screen RAMs, Pac-Man eating the fruit, the end of the frame inside the routine) the hook lets the ROM run its own instruction.
Frame timing: the cycle count of EVERY frame is compared (original vs readable): identical, so the frame still finishes in time with the cycles charged.
