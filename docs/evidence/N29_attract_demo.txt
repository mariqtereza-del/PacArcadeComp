What is replaced (ROM addresses, no ROM bytes): choosing which demo ghost/Pac-Man counter to compare (4D3A / 4D32 against the 21h / 20h / 22h / 24h values) and the jump to the demo end (4DA0-4DA3 flag, hand-over to 058E which is native since N26), the sum test of the two counters 4DD0 + 4DD1 against 6, the call chain of the demo's frame step (1017, 0E23, 0C0D, 0BD6, 05A5, 1EFE, 1F25, 1F4C, 1F73: the calls are made exactly as the ROM makes them; the routines behind them are not native yet and belong to later steps), and the direction hand-over of the demo at 05A5 (reads 4DB5, clears it, builds the direction word from 4D30 and a table, stores it at 4D26 through RST 18h; RST 18h is reached as the ROM reaches it).
How it works: the same runner as N28: a run starts at one of the entry addresses and ends at the first instruction that leaves the straight-line code (CALL, RST, RET, JP, or a taken RET Z / JP Z), or when the code runs straight on into another entry address. New instruction kinds for this step: LD B,A; LD (nn),HL; XOR n; SUB B; CP n; ADD A,B; JR NZ; JP Z; RET Z. Everything is accounted for as the Z80 does it: T-states, opcode fetches, flags incl. the undocumented ones, WZ, stack bytes (RET Z takes 11 or 5 T-states, JP Z 10 either way).
