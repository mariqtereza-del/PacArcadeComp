S34D evidence: PURIST MODE / RESET TO DEFAULTS (2026-10-21)

What was built
  The menu item PURIST MODE is now two rows, "PURIST MODE /" and "RESET TO DEFAULTS" (the label does not fit one row of the menu box). Enter on it asks ("press Enter again"); the second Enter resets. Any other command cancels the question.
  The reset puts every setting back to the value Menu::Settings{} has (the same as a fresh settings.cfg): overlay, scanlines, scaling, pacing, window frame, key panel, vibration (full), pause when the window loses focus, hints, lightbar (on), run summary, CRT mask/glow/curve/surround, pad symbols, RULES (ORIGINAL), the test cheat, and lives/bonus/difficulty/ghost names (3 lives, bonus at 10000, normal, normal).
  It does NOT touch: controls.cfg (key and pad bindings and one-button start), the saved high score, records, statistics, achievements, save slots. It cannot undo a rules.cfg file (the log says so).
  NO RESTART: the machine keeps running from the very next frame (log: "the game was not restarted"). Display, assist and rules settings change at once (RULES switches at a frame boundary, which was already allowed in mid-game).
  Lives, bonus life, difficulty and ghost names are DIP switches that the ROM reads once at power-on (routine 26D0, work RAM 4E6B-4E75; measured). New file src/app/dipnow.h: at the attract screen (main state 4E00 = 1) it runs the ROM's own routine 26D0 on a COPY of the machine with the new switch byte and puts the changed work RAM bytes back (CPU, stack, cycle count untouched), so the machine is exactly as if it had been powered on with those switches. During a game, a coin or the self test the change waits and the menu says APPLIES NEXT GAME (it was "RESTART NEEDED"). Changing these options in the menu now also needs no restart.
  settings.cfg: no `purist` line is written any more (21 settings); an old `purist on` line is reported in the log and ignored.
  The command-line flag --purist stays as a test aid (the old forced mode), so every old Purist hash is unchanged. Replay and scripted runs neither read nor write settings.cfg.
  Honest scope: "defaults" means the program's standard settings (vibration full, lightbar on, and so on), not "the arcade without anything extra". A loaded save state or rewind step restores the old RAM, including the old DIP bytes; the next attract screen applies the chosen switches again.

Tests (all PASS)
  tests/test_dip_live.sh   4 DIP sets x (correct apply, wrong apply = switch byte only): from the start of the game, every frame of the live-changed machine equals a machine powered on with those switches (0 frames differ; the wrong version differs in 3166 frames, so the test can see the difference); apply leaves CPU, cycle count and video memory alone and changes at most 8 work-RAM bytes; quiet() is false during the self test, a coin and a game. 25 checks.
  tests/test_reset_defaults.sh   1) reset pressed in the middle of a 7,273-frame game: all frame hashes equal the run without it, no restart; the first Enter only asks. 2) settings file after the reset equals the standard file, no purist line, old purist line ignored, controls.cfg and high score files byte-identical. 3) lives changed at the attract screen: put in at once, no restart, and from then on every frame hash equals a run powered on with 5 lives; differs from the 3-lives run. 4) lives changed during a game: the game goes on unchanged. 5) one Enter alone resets nothing.
  tests/test_menu.sh (941 checks), tests/test_integration.sh (21 settings), tests/test_purist.sh, tests/test_replay.sh, tests/test_cheat_invincible.sh and the fast native regression: see the result line in PROJECT_STATUS.md.
  A first version of test 3 used a reference whose restart was ignored by the replay (a replay forces its own DIP header) and a script whose first game started before the change; both were test-design faults, found, and replaced by a replay whose header carries the 5-lives switches and a script whose first coin comes at frame 4500.
