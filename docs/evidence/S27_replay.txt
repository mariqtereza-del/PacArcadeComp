== What was compared ==
One scripted two-minute play (7,273 frames at 60.606 Hz = 120 s), written by tools/analysis/oracle_replay.py --make into a replay file (format: src/app/replay.h): player 1 game (coin at frame 400, START 1 at 420, random joystick from 430), then a second game with two coins (4500, 4510) and START 2 (4530) and random joystick from 4600. The same file is read by both sides.
Per frame, a SHA-1 over memory 4000-4FFF (video RAM, colour RAM, 4800-4BFF as zeros, work RAM, sprite RAM) plus the 48 bytes written to 5040-506F (sound registers, sprite coordinates).
1. C++ run 1 = C++ run 2: all 7,273 hashes identical (determinism).
2. C++ = Python prototype (harness.py + the S18 mirror correction, exact 50,688-cycle frames): all 7,273 hashes identical.
3. Recorder: the inputs fed through Recorder while replaying were saved and equal the original file byte for byte.
4. The Windows build (mingw, run under wine) gives a log identical to the native one.
5. The run is a real game: 7,172 distinct frame states, the main state changed 38 times, a two-player game was seen. (The counters in the summary line include the attract-mode demo game, so 'games started' and 'dots' are not only the player's.)

== Limits ==
- This compares machine state (memory and I/O registers), not pictures or sound samples; those were compared separately in S20-S21 and S25.
- Both sides use the same frame model (exact frames, mirrored memory, interrupt at the end of the slice); open question U1 (interrupt at line 224 versus end of slice) is therefore not tested by this.
- The prototype was run with the S18 mirror correction (MirrorBoard), as in S18; the original harness.Board without mirrors would differ at frame 297.
- Only the replay tool exists so far: the window app does not record or play replays yet (S27 could not touch src/app/main.cpp). tests/test_replay.sh is not in tests/run_all.sh (not in this step's file list).
