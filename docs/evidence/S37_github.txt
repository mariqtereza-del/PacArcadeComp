2. The ROM-byte scan (tools/export_github.sh runs it on every export)
  Input: all 10 ROM files of the Midway set (4 program, 2 graphics, 4 PROMs), 15,784 distinct 16-byte windows after dropping windows with fewer than 8 different values or fewer than 4 different steps between neighbouring bytes (zero padding, 00 01 02... counting runs).
  It searches every exported file as raw bytes; as hexadecimal text; and as number tables in text files (8, 16 and 32 bit values written in decimal or 0x notation, big endian, little endian and word swapped, separated only by commas, spaces or braces).
  Result on the final export: 0 hits. The first runs of the scan reported hits in tests/data/rom_tables.json, docs/evidence/S25_audio.txt, src/logic/mode_timers.h and the disassembly; those were fixed or excluded as listed above. (Some earlier false alarms, such as counting runs and numbers spread over several lines, led to the filters described.)
  Canary: 32 bytes of ROM program code written as a C array into src/zz_canary.h (temporary file) -> "ROM BYTES FOUND in src/zz_canary.h (matches pacman.6f at offset 512)", export deleted, exit code 1. The file was removed afterwards.
  Independent second check (separate script, no filter at all: all 21,795 distinct 16-byte windows of the ROM files, raw bytes only, every file of the export): 0 hits in the 458 files of the export.
  The release zip (MazeChase-1.0.1-win64.zip, 4 files) is scanned the same way after unzipping. With the strict filter: clean. The unfiltered second check finds 22,736 matches in MazeChase.exe: 21,290 are 16 zero bytes, 1,424 are zero runs with one other byte, 2 have 3 different values, 20 are 15 or 16 different values and these are the counting run 00 01 02 .. 0F (18 times) or 00 00 01 .. 0E (2 times), as found in the C library part of any program. None is ROM data. The exe contains no ROM: it reads the ROM from the player's file at run time (src/board/romset.cpp).
  The release zip content: MazeChase.exe, README.txt, REPORT-A-PROBLEM.bat, THIRD-PARTY-LICENSES.txt (now with the z80 licence). tools/package.sh was run again for that. MazeChase.exe differs from the exe the user tested (S36) in 5 bytes of the file header (build time stamp); everything else is byte for byte identical (cmp -l).
