T01e evidence: movement of Pac-Man and the four ghosts as readable code (src/logic/movement.h) versus the ROM (2026-10-15)

== What was written ==
src/logic/movement.h: Pac-Man's movement (ROM 1806: speed pattern, joystick, turning, walls, the move and the pull to the middle of the tile, tunnel rows, eating the fruit at 19A1, the dot part 19CD reuses the T01c code, and his walk in the attract demo / between levels 1A19) and the movement of Blinky, Pinky, Inky and Clyde (ROM 1B36, 1C4B, 1D22, 1DF9, which are four copies of one routine; here ONE function with a table of addresses; Blinky additionally has the Cruise Elroy speed-ups, ROM 20D7). Helpers: add a step (2000), pixel to tile (2018), tunnel test (205A), outside-the-maze-rows test with the tunnel wrap (1ED0), the turn-round routines (1EFE/1F25/1F4C/1F73), the 32-bit speed pattern shift. The queued tasks (08-0F, 17, the score tasks) are only queued, as the ROM does (T01c's task queue and timed event functions). Also changed: VideoRam (work_ram.h) can now see the colour RAM (a tile address can run into it) and returns BF for 4800-4BFF like the machine; the T01c and T01d tests were rerun and still pass.

== How it was proved ==
Compared after every call: ALL work RAM (4C00-4FEF), the whole video RAM, the colour RAM (except the bytes under the stack pointer used by the routine's own calls). The joystick bytes the ROM reads (5000 and 5040) are given to the readable version.
Part A (live): a scripted player for 3,000,000 frames; at every entry of 1806, 1B36, 1C4B, 1D22, 1DF9 the readable version gets a copy of the memory; at the return both must be identical.
Part B1: Pac-Man alone for every combination of: mode (maze rows / tunnel rows x normal play / attract demo / level change) x direction (4) x step (4 + standing) x pixel position inside the tile (8 x 8) x joystick (16) x walls on the tile and its four neighbours (32): 3,932,160 calls.
Part B2: each ghost alone for every combination of: step (5) x pixel position inside the tile (64) x turn-round flag x blue x tunnel colour x door colour x 4E02 = 22 or not (32) x tile class (the tunnel ends 1D and 3E, below 21, from 3B on, inside) (5) x 4 random fillings: 819,200 calls.
Part B3: 1,000,000 random runs of each of the five routines (random speed patterns, flags, tiles, steps, directions, joystick, fruit, colour bytes; the task queue pointer kept inside its page).

== Honest limits ==
1. The readable code is not used by the game yet; the full 85-minute regression was not rerun (no game code changed).
2. In the live play the scripted player spends most calls in the attract demo / level-change walk (about 76% of Pac-Man's calls) and only part in real joystick play; real joystick steering, walls and tunnel rows are covered by the exhaustive Part B1 and B3. Live play did not reach Cruise Elroy or fruit eating (0 cases); both are proved by the isolated runs (and the broken versions of them are caught).
3. Directions in memory are taken to be 0-3 (the ROM looks them up in a table; values above 3 do not occur) and the task queue pointer is kept inside its page (the ROM would write anywhere else). A full timed-event table (16 slots) is not modelled, as in T01c.
4. Tile addresses that lead above 4C00 (work RAM) are not modelled; they cannot occur (the largest is 493F).
5. NOT part of T01e: the ghost direction tasks (ROM tasks 08-0F, which call the T01d chooser), collisions, the ghost house release, the mode timers (T01f).
tests/run_all.sh ALL TESTS PASSED (short versions of the five logic tests); tests/test_purist.sh PASS; tests/test_replay.sh PASS. Game code unchanged.
