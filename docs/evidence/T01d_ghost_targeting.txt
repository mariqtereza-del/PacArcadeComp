T01d evidence: ghost targeting (four target rules) and the direction chooser as readable code (src/logic/ghost_targeting.h) versus the ROM (2026-10-15)

== What was written ==
src/logic/ghost_targeting.h: the direction chooser (ROM 2966, with the distance helper 29EA and the multiply helper 2A12) and the four target tasks: Blinky 2730, Pinky 276C, Inky 27A9, Clyde 27F1. Rules as written: never turn back; walls (maze tile code & C0 = C0) are skipped; the neighbour nearest the target by squared distance wins and on a tie the LATER direction (right, down, left, up order of the ROM table) wins; if every way is blocked the ghost keeps its direction. Scatter corners for the even phases of a running maze (Blinky only when not Cruise Elroy); chase: Blinky = Pac-Man's tile, Pinky = four steps ahead of Pac-Man, Inky = twice the point two steps ahead minus Blinky's tile, Clyde = Pac-Man's tile unless nearer than 8 tiles (squared distance under 64). The ROM's quirks are kept on purpose (the 16-bit carry that makes Pinky's and Inky's 'ahead' point go sideways when Pac-Man moves up/left). The chooser's working bytes (4D3B-4D45, 4DC7) are written exactly as the ROM does. VideoRam reads outside 4000-43FF now return 0 (work_ram.h).

== How it was proved ==
Compared after every call: ALL work RAM (4C00-4FEF), the whole video RAM, the colour RAM (except the bytes under the stack pointer used by the routine's own calls); for the chooser also its answer in A (direction) and HL (step).
Part A (live): a scripted player for 3,000,000 frames; at each entry of 2966, 2730, 276C, 27A9, 27F1 the readable version gets a copy of memory (and the registers); at the return both must be identical.
Part B1: 2A12 for all 256 inputs; 29EA for every pair of values on each axis (131,072 pairs).
Part B2: the chooser alone for EVERY ghost tile of the maze area (959 tiles whose four neighbours are on the screen) x EVERY target tile of the maze area (a,b = 1E-40) x 4 directions, random walls around the ghost: 4,699,100 calls.
Part B3: 1,000,000 random choosers (any such ghost tile, any 16-bit target, any direction, random memory and maze).
Part B4: 1,000,000 random runs of each of the four target tasks (random phase, Cruise Elroy, level state, tiles, directions, Pac-Man's step bytes incl. odd ones to exercise the carry).

part B3: 1000000 random choosers (any ghost tile that has its neighbours on the screen, any target, any direction, completely random memory and maze): differences so far 0

== Honest limits ==
1. The readable code is not used by the game yet; the full 85-minute regression was not rerun (no game code changed).
2. In live play the scripted player never reached Cruise Elroy (0 cases); Elroy is proved by the 1,000,000 isolated Blinky runs. Live play also only reached the first level, and Clyde scattered rarely live (631 times); the isolated runs cover all of it.
3. The chooser's exhaustive check covers target tiles of the maze area (1E-40 each axis) and ghost tiles whose four neighbours lie in the video RAM (those outside never occur in the maze); wider targets and random memory are in B3.
4. The ghost's own tile outside the video RAM and the effect of the chooser on tiles beyond 4000-43FF are not modelled (reads return 0).
5. Moving the ghosts themselves (speed, turning at tile centres, tunnels) and the mode timers are NOT part of T01d (T01e, T01f).
