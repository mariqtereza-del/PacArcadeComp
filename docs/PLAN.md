# Pac-Man PC Port Plan, version 2.0 (2026-10-06)
Authoritative roadmap. Generated by tools/make_plan.py from tools/plan_data.py. Do not hand-edit this file; edit the data file and regenerate.
The user-facing version is docs/Pac-Man_PC_Port_Plan.html (also published as an artifact).

Approach (unchanged): Track A first: a C++ board emulator runs the player's own ROM (accuracy comes from running the original program), wrapped in a modern PC front end. Track B (readable rewrite) is optional (T01). The ROM is never bundled. Modern features live outside the accuracy core, with a Purist mode.
Reference oracle: the Python prototype in tools/analysis (S05). Every C++ step is compared against it or against ROM data or documented arcade values.

Status now: 146 steps. VERIFIED 88, PARTIAL 1, AWAITING USER TEST 1, NOT STARTED 56.

## Rules for every step
1. One primary objective per step.
2. Read only the files the step names. Do not re-read the whole project.
3. Verify before extending: run the step's VERIFY. Code written is not a finished step.
4. Never build on an unverified step. If S(n) fails, fix S(n) before S(n+1).
5. Never redo VERIFIED work. Replacing working code needs a written reason plus regression tests.
6. Checkpoint after every step: update PROJECT_STATUS.md, the plan status, evidence, known limits, next step.
7. Keep each step small enough to finish inside one context. If it looks big, split it before starting.
8. Spend tokens on inspecting, implementing, testing, fixing, documenting. No long tutorials.
9. Do not ask the user technical questions. Investigate, choose the safest option, record the decision. Ask only for human decisions or information only the user has.
10. Never claim success without evidence. 'It compiles' and 'a window opened' do not prove hardware is emulated correctly. Prefer exact comparison against the prototype oracle, ROM data, or documented arcade values.

## Step template (each docs/steps/SNN.md follows it)
OBJECTIVE, WHY, STARTING STATE, READ FIRST, MAY TOUCH, IMPLEMENT, DO NOT, VERIFY, SUCCESS CRITERIA, IF FAILURE, DOCUMENT, CHECKPOINT. Plus: lane, dependencies, files the step may touch, evidence to record.
