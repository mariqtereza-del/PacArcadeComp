# STEP X02: Test scenarios (set-ups for tests)
Status: **VERIFIED**   Lane: EXTRAS   Depends on: X01, S34B

OBJECTIVE: A test helper that puts the machine into a chosen situation by writing memory (fruit on the screen, a power pellet just eaten with ghosts near, one dot left, level 17), so extras can be tested on real machine behaviour without playing for an hour.

WHY: The recorded real game has no fruit, no ghost eaten and no round clear; the achievements and trainers need those tested with the real ROM running.

STARTING STATE: The steps it depends on are VERIFIED. Rules shared by every X step are at the top of tools/plan_data_x.py (assist rule, Purist off, new code in new files).

READ FIRST: docs/notes/ram_map.md, PROJECT_STATUS.md and the files named in MAY TOUCH

MAY TOUCH (only these): tests/scenario.h (new), tests/test_scenarios.*, docs/notes/ram_map.md

IMPLEMENT:
- tests/scenario.h: functions that run the real machine to a moment, then poke a few bytes (documented one by one with the RAM map), and run on.
- Prove each scenario on the real ROM: fruit appears and can be eaten, 4 ghosts eaten give 200+400+800+1600, last dot clears the round and the next level starts, level 17 loads its tables.
- These pokes are for tests only; the game never does them (except the assists in later steps).

DO NOT:
- No change to the emulation: the extra only reads memory, lives outside the machine, or is an assist (the game then stops counting for records).
- The Reset to defaults button puts it back to its default unless this step says otherwise; replay hashes must stay identical (tests/test_purist.sh, tests/test_replay.sh).

VERIFY:
- Each scenario produces the expected events from X01
- Scripted replay and Purist hashes unchanged

SUCCESS CRITERIA: All checks pass; replay and Purist hashes identical.
