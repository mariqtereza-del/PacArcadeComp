# STEP N17: Long routines: a native routine that can be paused after a number of cycles (prototype)
Status: **VERIFIED**   Lane: NATIVE   Depends on: N16

OBJECTIVE: Build and prove the mechanism for routines that the interrupt can cut in the middle: the native routine runs for the cycles the frame has left, stops exactly where the ROM routine would be when the interrupt arrives, and continues next frame. Prototype on the screen clear (video RAM and colour RAM fill).

WHY: This is the mechanism behind the 0.8% of frames found in the timing study.

STARTING STATE: The earlier N steps are VERIFIED.

READ FIRST: docs/notes/rom_routines.md (from step N01), the step's evidence files

MAY TOUCH (only these): src/game/ (new native code), src/rules/, src/data/, tests/test_native_*, tests/lockstep.h

IMPLEMENT:
- src/game/sliced.h; the screen clear as the first user; lockstep over the frames where it is cut.

DO NOT:
- The game you play must stay identical: every step is proved frame by frame against the original ROM run, including the exact cycle count of every frame.
- The Z80 question: while the game was being converted (N01 to N49b) the Z80 kept running every routine that was not replaced yet, and the default state (RULES: ORIGINAL) ran the original ROM routines. Since N49c the program has no Z80 at all: it exists only as the reference in tests/oracle, and RULES: ORIGINAL runs the native translation of the original routines with the original numbers.
- Never put ROM bytes into the source: tables come from the player's ROM at run time (src/data/), tools/export_github.sh must stay clean.
- If a step would take longer than about 20 minutes, stop and split it (a, b) in the plan; do not squeeze it in.

VERIFY:
- Isolated proof: each replaced routine, called with the real entry states collected from the coverage runs and with random states, gives the same memory writes, the same registers the callers use and exactly the same cycle count as the ROM routine (tools: the cycle meter and tests/lockstep.h)
- Lockstep: the original machine and the machine with all replaced routines play the coverage runs and the replay test (evidence run 1,000,000 frames, about 7 minutes; 3,000,000 at milestones), compared after every frame: all memory, I/O writes, the cycle count of the frame and the CPU registers; also with garbage in the registers the routines leave alone
- A deliberately wrong version is caught
- Progress meter: the number of ROM instruction addresses still executed in the coverage runs, printed before and after

SUCCESS CRITERIA: Zero differences; the progress meter goes down.
