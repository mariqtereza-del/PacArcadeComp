# STEP I01: Frame rate: 30, 60, 75, 100, 120, 144, unlocked
Status: **VERIFIED**   Lane: ITERATION   Depends on: N55

OBJECTIVE: DISPLAY > FRAME RATE with seven choices (and --fps). The machine keeps ticking at 60.606 Hz; above 60 the sprites are drawn between two ticks so the movement is smoother, like a modern game.

WHY: User request (2026-10-28): run smoother at higher frame rates without changing any game logic.

STARTING STATE: N55 VERIFIED (release 2.0.0).

READ FIRST: src/app/main.cpp (main loop, render block), src/video/sprites.cpp, src/app/menu.cpp

MAY TOUCH (only these): src/app/main.cpp, src/video/sprites.cpp, src/app/menu.cpp, src/app/menu.h, tests/test_fps_hdr.*

IMPLEMENT:
- Setting frame_rate (30, 60, 75, 100, 120, 144, unlocked) in the menu and settings.cfg, --fps on the command line; Purist mode is always 60.
- A limiter with four modes (classic 60 as before; vsync on with pictures built at the chosen rate; vsync off held by a timer; unlocked) chosen from the screen's refresh rate; the log says which one.
- render_sprites_lerp: sprites drawn between the previous and the latest tick (same picture and at most 8 pixels moved, otherwise the latest place); the tile layer is the latest tick's. Whole-pixel places give exactly the old picture.
- Smooth pacing (F6) is used only at frame rate 60 (kept both options as the user chose).

DO NOT:
- Do not change the game: the machine, the rules, the sound, the scores, the saved states and every replay hash must stay identical (the same 7,273-frame hash log at every setting).
- Do not put ROM bytes anywhere in the source, the export or the release.
