# STEP S34B: Pad buttons for the menu, pause, save, load and rewind
Status: **VERIFIED**   Lane: POLISH   Depends on: S34A

OBJECTIVE: Every system command that has a keyboard key (menu, pause, quick save, quick load, rewind) can also be done from the gamepad: the pad can open the menu, and save and load a state, with every pad type.

WHY: You can play and use the whole program from the couch with a DualShock 4, a DualSense or an Xbox-type pad, with no keyboard needed.

STARTING STATE: S34A exists. Today the pad can work the menu only after the keyboard has opened it, and F1, F2, F4 and Backspace are keyboard only (known limitation since S33).

READ FIRST: src/app/controls.*, src/app/menu.*

MAY TOUCH (only these): src/app/controls.*, src/app/menu.*, src/app/main.cpp (wiring)

IMPLEMENT:
- New pad commands: MENU, PAUSE, QUICK SAVE, QUICK LOAD, REWIND (hold). Default: MENU = right stick click (R3), which every pad has, including an Xbox-type pad made by DS4Windows. The others start unset (the menu already reaches Save and Load by pad); the player assigns them.
- The Bindings screen gets one row per new command with the pad column editable and the key column showing the fixed keyboard key (Esc, F1, F2, F4, Backspace); it must still fit the picture.
- With the menu open, the pad works it completely: d-pad, A select, B back, and the same pad button that opens it also closes it.
- The same rules as the keyboard: Purist mode locks save, load and rewind on the pad too; none of this can change an emulated input bit; coin and start keep working.
- Help panel and menu show the pad button for each command that has one.
- The controls file gets lines for the new pad commands; older files still load.

DO NOT:
- No change to emulated input bits.
- Do not use a button that is already Coin or Start by default.

VERIFY:
- Unit test: new pad commands bind, swap, clear and save/reload like the others; a button is never on two commands
- Real-window run with a simulated pad (SDL virtual joystick) is not possible from outside the program, so the pad event handling is exercised by a small test harness that feeds button events to the same functions
- Scripted replay hashes unchanged (tests/test_purist.sh, tests/test_replay.sh)

SUCCESS CRITERIA: All checks pass; the controls file holds the table the screen shows.

IF FAILURE: Stop. Re-run only this step's VERIFY command. Undo the last edit and retry. Compare against the Python prototype (tools/analysis) as the reference. Write what you found in docs/evidence/S34B_failure.md. Do not start the next step.

DOCUMENT: In PROJECT_STATUS.md set this step's row (status, date, evidence path), add a line under Changes and Known limitations, and set Next step. Set the status in tools/plan_data.py and run python3 tools/make_plan.py.

EVIDENCE TO RECORD: docs/evidence/S34B_pad_system_buttons.txt

CHECKPOINT: Run sh tests/run_all.sh (all earlier tests must still pass), then sh tools/checkpoint.sh S34B and send the zip to the user.

USER ACTIONS (tell the user in plain click-by-click words; see the Standard test routine in the plan page):
- Menu: with only the pad (keyboard untouched) press the MENU button, move with the d-pad, choose Save state, close the menu, play on, open it again and choose Load state: it must restore the saved moment.
- Repeat with each pad you have: DualShock 4, DualSense and the DS4Windows (Xbox-type) one.
- Assign Quick save and Quick load to two buttons you like and use them in a game; hold the Rewind button.
- Switch Purist mode on: save, load and rewind must say LOCKED and do nothing from the pad.
