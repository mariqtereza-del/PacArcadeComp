# STEP S34A: Controls screen: every command with its key and pad button
Status: **VERIFIED**   Lane: POLISH   Depends on: S34

OBJECTIVE: A Controls page in the menu that lists every command (Up, Down, Left, Right, Coin, Start 1, Start 2) with the keyboard keys and the gamepad button now assigned to it, and lets you change one command at a time.

WHY: You see at a glance what is bound to what, and can fix one control without going through the whole list. The key-help panel then shows YOUR keys, not fixed ones.

STARTING STATE: S32 remapping (F9 and F10 go through every command in turn, with the question in the window title) and the S34 menu exist.

READ FIRST: src/app/menu.*, src/app/controls.*

MAY TOUCH (only these): src/app/menu.*, src/app/controls.*, src/app/main.cpp (wiring, as in S31 to S34)

IMPLEMENT:
- Menu page Controls > Bindings: one row per command, showing key 1, key 2 and the pad button (names in the game's font: capital letters).
- Select a row and press Enter, then press the new key (or pad button): only that command changes. Backspace clears a slot, Esc cancels.
- If the key is already used by another command, say so on screen and swap the two (never two commands on one key without telling).
- Show the question and the answer inside the picture (not in the window title bar).
- The key-help panel shows the current coin and start keys and the movement keys from the bindings.
- F9 and F10 stay: they open the same screen. Everything is saved in controls.cfg as before; the file format stays readable by older versions.

DO NOT:
- No change to emulated input bits.
- No change to what Esc, F1 to F12 do (they stay reserved).

VERIFY:
- Unit test: changing one command leaves the others unchanged; swap on conflict; clearing; save and reload gives the same table
- Real-window run on a virtual screen: screenshots of the page before and after a change
- Scripted replay hashes unchanged (tests/test_purist.sh, tests/test_replay.sh)

SUCCESS CRITERIA: All checks pass; the screen shows what the controls file holds.

IF FAILURE: Stop. Re-run only this step's VERIFY command. Undo the last edit and retry. Compare against the Python prototype (tools/analysis) as the reference. Write what you found in docs/evidence/S34A_failure.md. Do not start the next step.

DOCUMENT: In PROJECT_STATUS.md set this step's row (status, date, evidence path), add a line under Changes and Known limitations, and set Next step. Set the status in tools/plan_data.py and run python3 tools/make_plan.py.

EVIDENCE TO RECORD: docs/evidence/S34A_controls_screen.txt

CHECKPOINT: Run sh tests/run_all.sh (all earlier tests must still pass), then sh tools/checkpoint.sh S34A and send the zip to the user.

USER ACTIONS (tell the user in plain click-by-click words; see the Standard test routine in the plan page):
- Esc > Controls > Bindings: check that every command is listed with the right keys and pad button.
- Change Coin to another key, leave the menu, check it works in the game; then change it back.
- Try to give one key to two commands and read the message.
- Close and reopen the program: the table must be the same.
