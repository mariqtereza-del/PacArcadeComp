# STEP S34C: Controller types, icon and button pictures (Xbox, DualShock 4, DualSense)
Status: **VERIFIED**   Lane: POLISH   Depends on: S34B

OBJECTIVE: The program recognises what kind of controller is plugged in (Xbox / XInput, DualShock 4, DualSense, or an unknown pad), shows a small icon of that controller type, and shows that controller's own button pictures (A B X Y, or cross circle square triangle) wherever a pad button is shown.

WHY: Immediate feedback: the Controls screen says "Coin: the button with the square" in pictures, not "button 4".

STARTING STATE: S34A and S34B exist. SDL's game-controller layer already treats Xbox, DualShock 4 and DualSense pads as the same standard pad; this step reads the type and draws the matching pictures.

READ FIRST: src/app/menu.*, src/app/controls.*

MAY TOUCH (only these): src/app/menu.*, src/app/controls.*, src/app/main.cpp (wiring)

IMPLEMENT:
- Show an icon for the controller in use (a small controller picture with the words PS4, PS5, XBOX or PAD): in the menu header, in the key-help panel and for a few seconds when a pad is plugged in or removed (the user's request, 2026-10-12).
- Ask SDL for the controller type when a pad is connected (Xbox 360 / Xbox One / XInput, PlayStation 4, PlayStation 5, other) and say it in the log and in the Controls screen.
- Draw the button pictures in code (no image files, nothing copied from anyone): Xbox A green, B red, X blue, Y yellow, LB RB LT RT, View, Menu; PlayStation cross, circle, square, triangle, L1 R1 L2 R2, Create or Share, Options, touch pad; unknown pads: plain names.
- Triggers, touch pad and the other extra buttons already bind as buttons (done in the S34B fix); here they only get their pictures (L2, R2, touch pad).
- Hot-plug between types updates the pictures at once (unplug the PS4 pad, plug an Xbox pad: the screen changes).
- Only one pad is used at a time, as now.

DO NOT:
- No change to emulated input bits.
- Do not claim a controller type was tested on real hardware when it was only simulated (the user has a DualShock 4, a DualSense and DS4Windows, so all three kinds can be tested for real).

VERIFY:
- Test with SDL virtual controllers set to each type: the right picture set is chosen for Xbox, PS4, PS5 and unknown
- Test: trigger and touch pad pictures appear in the Controls screen
- Real-window screenshots of the Controls screen for each type
- Scripted replay hashes unchanged

SUCCESS CRITERIA: Right pictures for every type; hashes identical.

IF FAILURE: Stop. Re-run only this step's VERIFY command. Undo the last edit and retry. Compare against the Python prototype (tools/analysis) as the reference. Write what you found in docs/evidence/S34C_failure.md. Do not start the next step.

DOCUMENT: In PROJECT_STATUS.md set this step's row (status, date, evidence path), add a line under Changes and Known limitations, and set Next step. Set the status in tools/plan_data.py and run python3 tools/make_plan.py.

EVIDENCE TO RECORD: docs/evidence/S34C_controller_types.txt

CHECKPOINT: Run sh tests/run_all.sh (all earlier tests must still pass), then sh tools/checkpoint.sh S34C and send the zip to the user.

USER ACTIONS (tell the user in plain click-by-click words; see the Standard test routine in the plan page):
- With your DualShock 4: the icon says PS4, and Esc > Controls > Bindings shows cross, circle, square, triangle, L1, R1, Share, Options pictures that match the buttons you press.
- Plug in the DualSense without restarting: the icon changes to PS5 and the pictures follow.
- Start DS4Windows so Windows sees an Xbox pad: the icon says XBOX and the pictures are A, B, X, Y (that is what Windows reports; the program cannot see the real pad behind DS4Windows).
