## How to work on this project (rules, short)
1. Do only the step named as Next step. Read only that step's file and the files it names.
2. Verify before extending; never build on an unverified step; never redo VERIFIED work.
3. After the step: run the FAST CHECK (below) and, only at the end of an X block, before a release or when a step touched shared code, the full `sh tests/run_all.sh` (about 85 minutes); update the status in tools/plan_data.py, run `python3 tools/make_plan.py` (rewrites the table below, docs/PLAN.md, step files and the plan page), add evidence, then `sh tools/checkpoint.sh SNN` and send the zip.
   FAST CHECK (agreed with the user 2026-10-15 to keep steps short; about 20 minutes): the new step's own test, the tests of the files the step touched (tests/test_menu.sh, test_surround.sh, test_cabinet.sh, test_crt_look.sh for display/menu changes), and tests/test_purist.sh and tests/test_replay.sh (hash checks). `/tmp/fast.sh`-style loop; list the tests run in the evidence file. The full regression is then run in the background once, at X48 (extras integration check) and before the release, and its result recorded.
4. The user is not a programmer: no technical questions, no programmer-level diagnosis. Give click-by-click instructions for anything they must do.
5. Never claim success without evidence.

## Decisions so far
- 2026-10-14: (1) X29 is only the progress line: no achievements of our own, only the ones taken from the RetroAchievements list (user). (2) Save-state rule for achievements changed (user): a loaded state no longer stops achievements; it still marks the game assisted for records, statistics and personal bests. Rewind, start-at-level and the cheat page are unchanged (cheat only = test unlocks). After a load the game stays eligible if it is a running one-player maze with 3 lives (DIP) and its per-game/per-round counts (fruit kinds, chains, clean-round streak) start again from the loaded round, because the saved state does not carry them.
- 2026-10-14: (X57 REMOVED, user: "You can remove the cheats") the cheat page and its code are deleted; the original request follows for history. The user asked for a cheat menu to test the ghost-chain achievements ("ghosts remain edible once I grab a pellet"). Decision (the safest, recorded without asking): new step X57. The cheat is an ASSIST (reason CHEAT HELP): the game stops counting for records, statistics and saved achievements. To still let the user see the achievements, while ONLY this cheat helped, achievements show their pop-up (header TEST UNLOCK - NOT SAVED) and the list says TEST, but they are never written to achievements.cfg and never count as unlocked. Cheat off in Purist, off in scripted runs, never saved in settings.cfg. Reach: Esc > GAME OPTIONS > CHEATS.
- 2026-10-14 (user request): steps X13 to X21 (slot thumbnails, resume, level inventory/selector, slow motion, frame advance, trainers), X23 (statistics history), X30 to X39 (replays, ghost runs, daily challenge) REMOVED from the plan; ids of the remaining steps are unchanged (gaps are intended). X24 now depends on X22; X48 no longer depends on removed steps and now also needs X12. Later the same day the user also removed online steps X50 to X52 (leaderboards) and X55, X56 (spectating, live race); online now keeps only X49 (design), X53 (connection), X54 (turn-based two-player). X49 and X54 carry a NOTE. src/app/assist.h keeps its unused reasons.
- Route: Track A first (C++ board emulator runs the ROM, accuracy by construction); Track B (readable rewrite) is optional (T01).
- The ROM is never bundled. Loaded at runtime from the player's own file and checksum-verified. `roms/` is excluded from backups and releases.
- Target ROM set: Midway "pacman" (MAME set `pacman`). Puck-Man files are in the zip, unused; possible later version selector.
- Modern features live outside the accuracy core. A Purist mode turns them all off.
- Language: C++17 with SDL2. Rust rejected (cannot download Rust's Windows libraries here).
- Windows build: MinGW-w64 cross compiler + SDL2 2.32.10 MinGW package (GitHub release). `tools/build_windows.sh`. One self-contained .exe (about 1.9 MB). No Wine here, so Windows behaviour is confirmed only by the user's reports.
